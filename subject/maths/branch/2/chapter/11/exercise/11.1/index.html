Q1

Add two 4-digit numbers using the steps we have written down. Make sure you follow the steps precisely; do not perform any action that is not explicitly mentioned. Are you able to obtain the correct result?

Answer: Let's add 4567 and 8924 using the algorithm:
1. Align right to left:
  4567
+ 8924
2. Rightmost digits: 7 + 4 = 11. More than 10. Write 1. Carry = 1.
3. Next column (tens): 6 + 2 + 1 (carry) = 9. Less than 10. Write 9. Carry = 0.
4. Repeat (hundreds): 5 + 9 + 0 = 14. More than 10. Write 4. Carry = 1.
5. Repeat (thousands): 4 + 8 + 1 (carry) = 13. More than 10. Write 3. Carry = 1.
6. No more digits on left. Step 5: Carry is 1, so write 1 to the left.
Result: 13491. Yes, the correct result is obtained.

Q2

What happens if you add a 5-digit number to a 3-digit number. Do our steps handle this situation correctly?

Answer: In the steps as written, there is no instruction for what to do when one number runs out of digits before the other. To make the algorithm work for a 5-digit and a 3-digit number, we need to treat the blank spaces on the left of the 3-digit number as zeros (for example, writing $345$ as $00345$) so that Step 3 always has two digits to add in every column.

Q3

Why is it important to align the columns from right to left?

Answer: Aligning from right to left lines up digits with the same place value — ones with ones, tens with tens, and hundreds with hundreds. If we aligned them from left to right when the numbers have different lengths, we would end up adding digits of different place values (like hundreds to thousands) and get a wrong answer.

Q4

In Step 3, why cannot the value of carry be more than 1?

Answer: The largest single digit is 9. Even if we add two 9s along with a carry of 1 from the previous column, the largest possible sum is $9 + 9 + 1 = 19$. Since 19 is less than 20, the tens digit of the sum — which becomes the new carry — can never be greater than 1.

Q5

What happens if we do not include the fifth step in the algorithm above? Give examples where the algorithm will work correctly and where it will fail to work.

Answer: Step 5 writes down the final carry of 1 at the leftmost end if there is a carry left over after the last column.
When it still works: It works whenever the leftmost column adds up to less than 10 (so the final carry is 0). For example, in $32 + 45 = 77$, the tens column is $3 + 4 = 7$ with carry 0, so skipping Step 5 still gives 77.
When it fails: It fails whenever the leftmost column produces a carry of 1. For example, in $85 + 42$:
- Ones column: $5 + 2 = 7$, carry = 0.
- Tens column: $8 + 4 + 0 = 12$. Write 2, carry = 1.
Without Step 5, the algorithm stops here and gives 27 instead of 127.
